Qwerty

Demo local para consultar archivos y hacer preguntas sobre los préstamos ficticios de la biblioteca Aurora. Open WebUI gestiona el acceso y las conversaciones. FastAPI recupera la evidencia y consulta MySQL.

  • Primera instalación en macOS

También puedes abrir Documentacion.html en tu navegador. Está en esta carpeta y sus enlaces funcionan al moverla o copiarla a Windows.

Uso diario en macOS

Si acabas de extraer el ZIP, completa primero la instalación de tu sistema. Cada instalación tiene sus propias cuentas y configuración.

  1. Abre MAMP y pulsa Start.

  2. Desde Terminal, en la carpeta del demo, ejecuta:

    ./iniciar_demo.sh

  3. Abre la dirección que imprime el comando, inicia sesión y selecciona Qwerty. Si acabas de crear la primera cuenta, registra el conector como indica la guía de instalación.

Estado y cierre

macOS mantiene los procesos del demo en marcha mediante launchd. Puedes cerrar Terminal y ChatGPT. Después de reiniciar el Mac o cerrar tu sesión de macOS, abre MAMP y vuelve a iniciar el demo. Servicios de usuario en macOS

./estado_demo.sh
./detener_demo.sh

El primer comando muestra el estado de los procesos del demo y de MAMP. El segundo cierra los procesos propios de Qwerty. MAMP y cualquier instancia de Ollama que hayas iniciado aparte se controlan desde sus aplicaciones.

Ollama local

Mover la carpeta

  1. Apaga el demo con ./detener_demo.sh.
  2. Mueve la carpeta completa. Incluye los archivos .env* y las carpetas ocultas .runtime, .venv y .venv_webui.
  3. En la carpeta nueva ejecuta ./iniciar_demo.sh. El lanzador prepara los servicios para esa ubicación y recupera las rutas de los adjuntos locales.

Estos pasos sirven para moverlo en el mismo Mac. En otro equipo prepara Python, PostgreSQL y MAMP según la guía de instalación.

Consultar PostgreSQL desde pgAdmin en macOS

  1. Abre MAMP y pulsa Start. Desde la carpeta de Qwerty, ejecuta ./iniciar_demo.sh para que arranque también PostgreSQL.

  2. Abre pgAdmin. Si ya tienes la conexión Qwerty local, ábrela y pasa al paso 4. Si es la primera vez, haz clic derecho en Servers, elige Register / Server y escribe Qwerty local en General / Name. El nombre solo identifica la conexión en pgAdmin.

  3. En Connection, usa los valores del archivo privado .env.webui, que se genera en la misma carpeta que este README. Ábrelo en tu editor para encontrar la línea WEBUI_PG_PASSWORD.

    Campo en pgAdmin Variable en .env.webui Valor de ejemplo en macOS

    Port WEBUI_PG_PORT 55442
    Maintenance database WEBUI_PG_DATABASE demo_webui
    Username WEBUI_PG_USER demo_webui
    Password WEBUI_PG_PASSWORD La contraseña de tu instalación

  4. Si acabas de registrar la conexión, pulsa Save. Abre Qwerty local / Databases / demo_webui / Schemas / public / Tables. Si ya tenías el árbol abierto, haz clic derecho en Tables y selecciona Refresh. Busca chat, user, file, model y function.

Los archivos de la instancia que inicia Qwerty en macOS están en .runtime/postgresql. La contraseña WEBUI_PG_PASSWORD corresponde al usuario de PostgreSQL. Qwerty en Windows

Sigue esta guía para instalar el demo en Windows y arrancarlo desde PowerShell. En una instalación ya preparada, inicia MySQL y PostgreSQL y ejecuta .\iniciar_demo.cmd desde la carpeta del demo.

Puedes abrir Documentacion.html en tu navegador para consultar todas las guías de la carpeta.

Para agregar archivos, consultar otras tablas o dar acceso a más personas, revisa las preguntas frecuentes.

Si el demo ya funciona, puedes ir directamente a la conexión de pgAdmin.

1. Instala las herramientas

Herramienta Para qué la usamos
Python 3.11 para Windows x64 Ejecuta FastAPI y Open WebUI en entornos separados. Instalar Python
MySQL 8.x Guarda los documentos y contiene la base de ejemplo de Aurora. Instala MySQL 8.4 con su configurador o usa un servidor 8.x que ya tengas. Instalar MySQL
PostgreSQL 16 o 17 con pgAdmin Guarda las cuentas y las conversaciones. Selecciona el servidor y pgAdmin en el instalador. Instalar PostgreSQL
Ollama Ejecuta el modelo local qwen3:1.7b. Instalar Ollama

Configura MySQL y PostgreSQL como servicios de Windows. Guarda el puerto y la contraseña administrativa de cada uno. En los ejemplos usamos 3306 para MySQL y 5432 para PostgreSQL.

MAMP para Windows incluye MySQL 5.7.24. Para el demo usa MySQL 8 independiente. Si otro servidor ya usa 3306, elige un puerto libre como 3307 al configurar el servidor nuevo. Versiones de MAMP para Windows

2. Prepara una copia limpia

Usa una copia que contenga app.py, iniciar_demo.cmd, datos/ y los archivos de requisitos. Si vienes del Mac, copia el código, los datos de ejemplo y las plantillas .env.example, .env.mysql.example y .env.webui.example. Prepara entornos y credenciales nuevos en Windows. Las carpetas .venv, .venv_webui y .runtime del Mac pertenecen a esa instalación.

Abre PowerShell en la carpeta del demo. Todos los comandos de esta guía parten de ahí.

py -3.11 --version
py -3.11 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
& .\.venv\Scripts\python.exe -m pip check

py -3.11 -m venv .venv_webui
& .\.venv_webui\Scripts\python.exe -m pip install -r requirements-webui.txt
& .\.venv_webui\Scripts\python.exe -m pip check

El primer entorno es para la API. El segundo es para Open WebUI y usa requirements-webui.lock.txt para fijar sus dependencias. Llamamos a cada Python por su ruta relativa para usar el entorno correcto.

3. Prepara MySQL

En Servicios de Windows comprueba que MySQL 8 esté en ejecución. El configurador pedirá la cuenta que puede crear las bases del demo.

& .\.venv\Scripts\python.exe configurar.py
& .\.venv\Scripts\python.exe configurar_mysql.py
& .\.venv\Scripts\python.exe verificar_mysql.py
Dato que pide el programa Qué escribir
Host 127.0.0.1
Puerto El de tu MySQL 8. Escribe 3306 si usas el puerto habitual. La sugerencia 8889 corresponde al Mac.
Administrador y contraseña La cuenta que configuraste para MySQL, normalmente root, y su contraseña.
Base nueva y usuario nuevo demo_documental si ambos nombres están libres. Para otra instalación usa nombres nuevos que empiecen por demo_.

El programa crea una base para la API y otra para Aurora. Con el nombre sugerido quedan demo_documental y demo_documental_aurora. También crea una cuenta de escritura para la API y una cuenta que solo puede leer la vista ficticia. La última comprobación debe mostrar MySQL conectado y tres filas en la vista de Aurora.

4. Prepara PostgreSQL desde pgAdmin

  1. Abre pgAdmin. En Servers, abre Register y elige Server. Escribe un nombre como PostgreSQL local y conecta con 127.0.0.1, el puerto del servidor, el usuario postgres y la contraseña elegida en el instalador.
  2. En Login/Group Roles, abre Create y elige Login/Group Role. Crea demo_webui, ponle una contraseña en Definition y habilita Can login en Privileges. Déjalo como usuario normal.
  3. En Databases, abre Create y elige Database. Crea demo_webui y selecciona demo_webui como propietario. Si el nombre ya existe, elige uno nuevo para esta instalación.
  4. Guarda la conexión del demo desde PowerShell.
& .\.venv\Scripts\python.exe configurar_webui_windows.py

Ingresa el host, el puerto, la base y la cuenta que acabas de crear. Usa la contraseña de demo_webui. El programa comprueba la conexión y genera .env.webui con MANAGE_LOCAL_POSTGRES=false, porque Windows administra PostgreSQL como servicio.

5. Conecta Ollama local

Abre Ollama desde Inicio y ejecuta lo siguiente en PowerShell.

ollama pull qwen3:1.7b
ollama list
(Invoke-RestMethod "http://127.0.0.1:11434/api/tags").models.name

La lista debe incluir qwen3:1.7b. Si PowerShell todavía no encuentra ollama, abre una ventana nueva. La primera descarga necesita conexión a Internet. La búsqueda en documentos también descarga un modelo de representaciones la primera vez que lo necesita.

Revisa estos valores en el archivo .env de la carpeta del demo. Si tu Ollama usa otro puerto, escribe ese puerto en OLLAMA_URL y úsalo también al probar /api/tags.

OLLAMA_URL=http://127.0.0.1:11434
GENERATION_MODEL=qwen3:1.7b

FastAPI se conecta a Ollama por esa dirección. En Open WebUI usa Qwerty para que el conector pueda consultar MySQL y los documentos. Cómo se conectan los servicios

6. Arranca el demo y conecta el chat

Con MySQL y PostgreSQL en marcha, ejecuta:

.\iniciar_demo.cmd

El lanzador comprueba las bases y Ollama. Después inicia FastAPI y Open WebUI en segundo plano. Abre la dirección que imprime. Con la configuración de ejemplo es Open WebUI en 3187.

La primera cuenta que crees en Open WebUI administra el chat. Usa el correo y la contraseña de esa cuenta para registrar el conector.

& .\.venv\Scripts\python.exe conectar_openwebui.py

Acepta la dirección de Open WebUI que propone el programa. Para la API usa http://127.0.0.1:18129 si conservaste el puerto de ejemplo. En una instalación de una sola persona puedes dejar vacía la lista de usuarios autorizados. Después recarga la página, abre un chat nuevo y selecciona Qwerty.

7. Conecta la lógica con FastAPI

storage.py prepara la conexión con MySQL. app.py crea las tablas de la aplicación al iniciar y reúne la carga, la búsqueda y los cálculos.

Ruta Qué hace
GET /health Comprueba la conexión de la API con su base.
POST /documents Procesa un archivo y guarda los fragmentos y sus vectores.
POST /query Elige la consulta de Aurora o la búsqueda en documentos. Guarda la respuesta por propietario e identificador de solicitud.
POST /calculate Calcula sobre una tabla de archivo o una vista autorizada.

El conector envía la identidad del usuario, la hora y una firma HMAC. La firma se calcula con la clave del puente y los bytes exactos de la petición. La API la verifica antes de abrir los datos del propietario.

Con FastAPI en marcha, puedes comprobar una petición de lectura firmada. El ejemplo obtiene la clave del archivo local sin imprimirla.

import hashlib
import hmac
import time

import httpx
from dotenv import dotenv_values

config = dotenv_values(".env")
api = "http://127.0.0.1:" + config.get("API_PORT", "18129")
propietario = "comprobacion_construccion"
marca = str(int(time.time()))
mensaje = f"{propietario}\n{marca}\n".encode()
firma = hmac.new(config["BRIDGE_SECRET"].encode(), mensaje, hashlib.sha256)

with httpx.Client(timeout=10) as cliente:
    salud = cliente.get(api + "/health")
    salud.raise_for_status()
    assert salud.json()["storage"] == "mysql"

    assert cliente.get(api + "/documents").status_code == 401
    documentos = cliente.get(
        api + "/documents",
        headers={
            "X-Owner": propietario,
            "X-Time": marca,
            "X-Signature": firma.hexdigest(),
        },
    )
    documentos.raise_for_status()
    assert isinstance(documentos.json(), list)
    print("La API acepta la petición firmada.")

La lista puede estar vacía porque el perfil de comprobación todavía no tiene documentos. En una petición con cuerpo, la firma incluye también esos bytes.

       JSON_EXTRACT(t.response, '$.references[*].document') AS archivos_citados
FROM turns AS t
JOIN documents AS d ON d.owner = t.owner
WHERE d.id = @documento_id AND d.deleted = 0
  AND t.query = '¿Cuánto dura el préstamo?'
  AND JSON_SEARCH(t.response, 'one', CONCAT(d.id, ':v%:part%'),
                  NULL, '$.references[*].id') IS NOT NULL;

documents muestra el estado y la versión del archivo procesado. chunks muestra las partes del texto y el tamaño de su representación numérica. turns guarda la pregunta y el resultado de FastAPI. La última consulta busca la pregunta en la misma cuenta y exige una cita a ese documento. Si no devuelve filas, verifica que la respuesta en el chat haya citado el archivo que acabas de cargar.

SET @propietario = 'ID_DEL_PROPIETARIO';
SET @objetivo = NULL;

START TRANSACTION;

SELECT id INTO @objetivo
FROM documents
WHERE id = @documento_id AND owner = @propietario AND deleted = 1
FOR UPDATE;

DELETE FROM turns
WHERE owner = @propietario
  AND JSON_SEARCH(response, 'one', CONCAT(@objetivo, ':v%:part%'),
                  NULL, '$.references[*].id') IS NOT NULL;

DELETE FROM document_locations WHERE document_id = @objetivo;
DELETE FROM document_structures WHERE document_id = @objetivo;
DELETE FROM source_manifest WHERE document_id = @objetivo;
DELETE FROM document_attachments WHERE document_id = @objetivo;

WHERE id = @objetivo AND owner = @propietario AND deleted = 1;

Preguntas frecuentes de Qwerty

Esta guía explica cómo incorporar fuentes, dar acceso a más personas y personalizar el demo. Para instalarlo y hacer las primeras pruebas, abre el README de macOS o el README de Windows.

¿Dónde pongo los archivos que quiero consultar?

Guárdalos donde te resulte práctico. La carpeta datos/ contiene los ejemplos del demo. Para que el asistente lea un archivo, adjúntalo en un chat con Qwerty y envía /cargar. El servicio procesa el contenido y lo deja disponible para tu cuenta. Puedes preguntar en cuanto termine la carga, sin reiniciar.

Puedes cargar TXT, PDF con texto seleccionable, Excel en formato XLSX, CSV y JSON. Prueba con datos/politicas.txt y pregunta ¿Cuánto dura el préstamo?. Abre la referencia que acompaña la respuesta para comprobar los siete días naturales.

¿Cómo actualizo un archivo ya cargado?

Escribe /documentos para localizar su identificador. Adjunta la versión nueva y envía /sustituir ID, cambiando ID por el que te mostró el chat. Espera la confirmación y repite la pregunta. El asistente consulta la versión nueva sin reiniciar. Si el archivo nuevo falla, puedes seguir consultando la versión anterior y volver a intentar el reemplazo con un archivo válido.

¿Puedo agregar tablas de MySQL?

Sí. El chatbot consulta únicamente las tablas y vistas que el administrador autoriza. Una vista permite exponer un conjunto concreto de filas y columnas. Por ejemplo, prestamos_detalle reúne los préstamos y los nombres de los usuarios de Aurora.

  1. Prepara una tabla o vista con los campos que quieres consultar y concede permiso SELECT a una cuenta lectora.
  2. Agrega la tabla o vista y las columnas permitidas a SOURCE_CONNECTIONS en .env.sources. Si es otra base, configura también el alias, su conexión privada y las cuentas autorizadas.
  3. Reinicia el demo para que FastAPI lea la configuración. Prueba con una cuenta autorizada y verifica el resultado en MySQL.

Para las preguntas en lenguaje natural, menciona MySQL y el nombre de la vista cuando haya varias. El intérprete de natural_mysql.py está preparado para el vocabulario de Aurora. Si incorporas otro tema, puedes adaptar sus reglas y probar las nuevas preguntas. El comando /calcular permite indicar de forma explícita la fuente, la operación y las columnas. openwebui_pipe.py firma la identidad y llama a FastAPI. app.py verifica esa firma y decide si la pregunta corresponde a documentos o a una fuente MySQL. La API utiliza MySQL de MAMP para su evidencia y sus respuestas. La cuenta lectora de Aurora consulta únicamente prestamos_detalle.

Bases de datos de lectura

PostgreSQL y MySQL se consultan con SQLAlchemy; psycopg y PyMySQL son sus controladores. Un controlador permite que Python se comunique con el motor. El código no usa las credenciales administrativas de la aplicación para leer fuentes externas.

Preparar una fuente

Pide al administrador una cuenta con SELECT únicamente sobre las vistas o tablas necesarias. En PostgreSQL concede CONNECT a la base, USAGE al esquema y SELECT a la vista; configura default_transaction_read_only=on. En MySQL concede SELECT sobre la vista concreta. No se necesita SHOW VIEW: las columnas se definen en la política. Revoca privilegios heredados y comprueba las restricciones con esa cuenta. No utilices cuentas personales o administrativas para el chat.

Para practicar, crea una base vacía y exclusiva de demostración en cada motor. Ejecuta el esquema datos/aurora_postgresql.sql o datos/aurora_mysql.sql con una cuenta administradora únicamente en esa base nueva. Esos archivos preparan dos tablas relacionadas y una vista. No crean ni cambian usuarios. No los ejecutes sobre una base existente con datos reales.

Crea después un usuario lector y concede SELECT a prestamos_detalle. En MySQL, limita además el host autorizado del usuario a la red del backend. Las pruebas de esta revisión usaron bases nuevas con usuarios lectores separados. Las credenciales generadas quedaron fuera de la distribución.

Configurar el servidor

configurar.py prepara .env.sources vacío si no existe. Conserva este archivo privado. La API lo carga mediante iniciar_api.py. Este ejemplo usa valores de muestra que debes sustituir por los de tu base y tu cuenta de Open WebUI.

SOURCE_PG_READ_URL=postgresql+psycopg://LECTOR:CLAVE_ESCAPADA@HOST:5432/BASE_DEMO
SOURCE_MYSQL_READ_URL=mysql+pymysql://LECTOR:CLAVE_ESCAPADA@HOST:3306/BASE_DEMO
SOURCE_CONNECTIONS='{"aurora_pg":{"url_env":"SOURCE_PG_READ_URL","allowed_owners":["ID_USUARIO"],"tables":{"prestamos_detalle":["id","usuario_id","nombre","libro","importe","fecha"]}},"aurora_mysql":{"url_env":"SOURCE_MYSQL_READ_URL","allowed_owners":["ID_USUARIO"],"tables":{"prestamos_detalle":["id","usuario_id","nombre","libro","importe","fecha"]}}}'

Una contraseña con caracteres reservados debe codificarse para una URL. No pegues una cadena real en el chat ni en capturas. La API se ejecuta en tu Mac; 127.0.0.1 identifica el mismo equipo donde está MAMP. Los ejemplos no habilitan conexiones por sí solos.

allowed_owners contiene IDs de cuentas, no correos. Cada alias se limita a una base por su URL y a las tablas, esquemas y columnas de tables. Para otro esquema PostgreSQL usa "esquema.vista". No se admite que el usuario envíe una URL o SQL. public_demo=true habilita explícitamente un alias para todas las cuentas del servidor: úsalo solo con datos ficticios destinados a todos.

Reinicia la API después de cambiar la política. Dentro del chat, /conectar ALIAS verifica tu autorización y genera un registro privado. Conservar ese ID no permite compartir acceso: se valida el propietario en cada cálculo y se revalida la política. /revocar ID cancela ese registro. Para retirar acceso general elimina el alias, retira allowed_owners o revoca los permisos de la base; reinicia la API. Cambiar la URL o la vista actualiza la fuente sin migrar conversaciones.

Qué ocurre durante una consulta

/calcular valida la fuente, tabla, columnas, filtros y operación. Abre una transacción de lectura y obtiene como máximo 5001 filas: si hay más de 5000, rechaza el resultado completo en vez de presentar un total parcial. Las operaciones se ejecutan sobre esas filas autorizadas con decimales exactos. Hay límites de conexión y de ejecución SQL de cinco segundos. No es un motor analítico para millones de registros; prepara una vista acotada si hace falta.

El resultado conserva alias, tabla, columnas, identificadores pertinentes y hora UTC. Los números de fila de la base son posiciones del resultado, no una identidad estable: utiliza identifiers.id para localizar el registro. No hay SQL generado por un modelo, credenciales en respuestas ni copia automática al índice vectorial. Un resultado puede cambiar entre consultas; exportar una instantánea y cargarla como archivo es una decisión explícita.

Ante error de credenciales, permisos, servicio o columna, se muestra un mensaje sin la cadena de conexión. El diagnóstico detallado corresponde al administrador local. Los permisos de solo lectura deben existir en la base además del control de la aplicación.

Permisos mínimos de ejemplo

Estos comandos los ejecuta el administrador dentro de la base nueva. LECTOR representa una cuenta previamente creada con una contraseña privada. No se incluyen contraseñas en el ejemplo.

PostgreSQL:

GRANT CONNECT ON DATABASE BASE_DEMO TO LECTOR;
GRANT USAGE ON SCHEMA public TO LECTOR;
GRANT SELECT ON public.prestamos_detalle TO LECTOR;
ALTER ROLE LECTOR SET default_transaction_read_only=on;

MySQL, sustituyendo HOST_BACKEND por el host autorizado al crear la cuenta:

GRANT SELECT ON BASE_DEMO.prestamos_detalle TO 'LECTOR'@'HOST_BACKEND';

Estos GRANT agregan permisos; no eliminan privilegios que una cuenta ya tuviera. Utiliza una cuenta nueva y comprueba que INSERT y la lectura de tablas no autorizadas fallen. El script de datos no administra usuarios ni amplía permisos automáticamente.

Formatos y ubicación de la evidencia

Formato Qué conservamos Cómo verificarlo
TXT Unicode UTF-8 Texto y líneas, con posición de palabras Abre la referencia y consulta location.line_start y line_end
PDF con texto Página real y posición de palabras Contrasta el fragmento con esa página del archivo
XLSX Hojas, encabezados, filas, tipos y celdas de origen Revisa sheet, row y range
CSV UTF-8 Encabezados, filas, columnas y tipos Revisa row y columns; el encabezado es la fila 1
JSON Campos anidados y listas sin repetir cada rama completa Revisa path: $ es la raíz, [0] el primer elemento

XLS y XLSM no están habilitados. Exporta una copia XLSX sin macros. No ejecutamos macros ni fórmulas. Para una fórmula Excel se utiliza su resultado guardado, si existe; sin ese resultado queda un valor ausente y una advertencia. Un PDF escaneado necesita reconocimiento óptico de caracteres, OCR, antes de cargarlo. No se ha incorporado OCR automático.

Cargar una hoja o un CSV

Con biblioteca.xlsx adjunto, escribe /cargar hoja=Prestamos. Para nombres con espacios utiliza /cargar "hoja=Mi hoja". Sin selección se procesan las hojas dentro de los límites. /estructura ID muestra hojas, conjuntos de datos disponibles, columnas y advertencias. Cada carga tiene su propio ID; reemplaza ID por el valor recibido, sin comillas adicionales.

El separador CSV se detecta entre coma, punto y coma, tabulador y barra vertical. Para especificar punto y coma y coma decimal: /cargar separador=; decimal=,. Se admite UTF-8 con o sin marca inicial BOM. Los identificadores como 001 se conservan como texto. Las fechas ISO se reconocen; otras fechas quedan como texto para evitar interpretar día y mes de manera incorrecta. No se adivinan separadores de miles.

Cálculos que podemos comprobar

Una suma no debe hacerse sobre los pocos fragmentos recuperados para redactar una respuesta. /calcular opera sobre todas las filas autorizadas de la tabla seleccionada. Por eso los cálculos requieren un comando estructurado: no ofrecemos traducción libre de preguntas a SQL.

Después de cargar prestamos.csv, usa /estructura ID. El conjunto de ese CSV se llama datos. Sustituye ID por su identificador:

/calcular {"document_id":"ID","dataset":"datos","operation":"sum","column":"importe"}

/calcular {"document_id":"ID","dataset":"datos","operation":"mean","column":"importe"}

/calcular {"document_id":"ID","dataset":"datos","operation":"count"}

/calcular {"document_id":"ID","dataset":"datos","operation":"rows","filters":[{"column":"usuario_id","op":"eq","value":10}]}

En Excel cambia dataset por Prestamos. En el JSON de demostración utiliza "dataset":"$["prestamos"]". También existen min y max. Los filtros admiten eq (igual), ne (distinto), gt (mayor), ge (mayor o igual), lt (menor) y le (menor o igual).

El chat presenta el resultado en una frase o una tabla. count cuenta filas. mean usa los valores numéricos presentes y deja fuera los que faltan. Si no hay valores disponibles, el chat lo indica. El importe de la demostración está expresado en pesos ficticios. rows muestra hasta 100 registros. La API conserva los filtros y las ubicaciones para revisar el cálculo.

Consultas a bases autorizadas

El administrador debe configurar primero las fuentes siguiendo docs/BASES_DE_DATOS.md. En el chat no se escriben contraseñas ni cadenas de conexión. /conectar aurora_mamp registra un alias autorizado para tu identidad. /conexiones muestra sus IDs y las vistas permitidas.

Estas consultas son en vivo: source.queried_at indica el momento UTC. No se indexa ni se conserva el contenido de la base como documento. En cambio, un archivo cargado es una instantánea con versión; hay que sustituirlo para actualizarlo. Para comparar dos fuentes, ejecuta el mismo cálculo, con los mismos filtros y columnas, en cada una y compara sus resultados y fechas.

/revocar ID_CONEXION invalida tu registro. El administrador puede retirar un alias o tu autorización en la política del servidor y reiniciar la API. No se permite SQL libre ni escrituras.

Sustituir, eliminar y conservar el historial

Adjunta el archivo nuevo y escribe /sustituir ID, con las opciones de hoja o decimal si hacen falta. Se genera una nueva versión y se retiran los fragmentos anteriores de las búsquedas. /eliminar ID retira el documento. Las citas antiguas que aparecen en conversaciones son evidencia histórica; /fuente comprueba la vigencia actual. /auditar contrasta el inventario de fragmentos con el manifiesto de la carga; no verifica la verdad del contenido.

Las carpetas internas las crean los servicios. No prepares directorios manualmente para subir archivos.
